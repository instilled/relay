# Flows, PR 1: flows replace rules — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One flow folder (`~/.relay/flows/<name>/flow.md`) — a trigger, steps with `after`/`if`,
and `ask` steps Relay raises itself — replaces `schedules.yaml`, `reactions.yaml` and everything
built on them.

**Architecture:** A new pure crate `rl-flow` parses `flow.md`, validates it, plans the step DAG and
decides what a firing does next. `rld` gains a `flows/` service that loads the folders, approves
them by hash, fires them on `when` and `on`, and carries out what `rl-flow` decides: step runs
through the supervisor, questions through the decision engine, state in two new ledger tables.
New code lands beside the old first (Tasks 1–11); then the old is switched off and deleted,
daemon first, then the panel and `rl`, then the shared types (Tasks 12–16).

**Tech Stack:** Rust 2024 workspace (`Cargo.toml` at the repo root, crates under `code/`),
tokio, rusqlite (numbered SQL migrations), serde + `serde_norway` (YAML), jiff, ratatui. Daemon
integration tests use `code/rl-daemon/tests/common` (`Harness`, `Conn`); agents in tests are
`code/fixtures/fake-agent`.

**Spec:** `docs/specs/2026-10-07-flows.md` — read it whole before starting; this plan argues
from it. This plan is PR 1 of four ("Flows replace rules"); PRs 2–4 get their own plans.

## Global Constraints

- Words: **flow** (the folder and its definition), **firing** (one run of a flow), **step**,
  **trigger** (`when`, `on`, by hand). No `rule`, `schedule` or `reaction` survives in a name,
  type, method, event, table, CLI word or the context pack at the end of the PR (Task 17 greps).
- `Run.flow`, `RunSpec.flow` and `Decision.flow` (the chain id) become `chain` (Task 1), so
  "flow" means one thing. A step run's `chain` is its firing's id.
- Flows live only in `~/.relay/flows/<name>/`; a folder name is `[a-z0-9][a-z0-9-]*`. A
  checkout's `.relay/` is never read for flows.
- `in:` is a path (`~` allowed), never a name, and must be a registered workspace or the flow
  does not load.
- A step run's cause is `flow:<flow>/<step>` (`Cause::Flow { flow, step }`).
- Placeholders (`{step.out}`, `{step.choice}`, `{step.note}`, `{event.summary}`,
  `{event.data.x}`) are spliced only into agent prompts and `ask:` text, in one pass (spliced
  text is never expanded again). A `run:` string or argv naming one is refused at load.
- A flow runs only when approved, by the sha256 of its folder less `runs/`. Nothing is approved
  automatically except through `rl flow edit` / `/flow edit` saving a flow that loads.
- Step runs: no tty, no input; the flow folder first on `PATH`; env `RELAY_FLOW`,
  `RELAY_FIRING`, `RELAY_STEP`, `RELAY_FLOW_DIR` (and `RELAY_LAST_FIRING` for a `when` firing,
  the event's `RELAY_EVENT*` for an `on` firing).
- `PROTOCOL_VERSION` (`code/rl-proto/src/lib.rs:21`) goes 3 → 4 (Task 16).
- No shims, no aliases, no migration of old rules: the old tables are dropped, and everything
  the old rules left is cleared with them — their runs, those runs' sessions, output, events,
  summaries and transcripts, the questions they raised and the runs those answers started, their
  job rows' keys in `row_order`, `hidden` and `summary_kept`, the reactor's cursor (Task 12).
- Never edit a shipped migration (`code/rl-ledger/src/migrate.rs:2`); add one.
- No module past ~800 lines. `handlers.rs` loses its rule handlers; flow handlers live in
  `rl-daemon/src/flows/rpc.rs`.
- Never invoke a real agent in a test. Never touch `~/.relay`; live checks use
  `RELAY_HOME=/tmp/<x>`, `tmux -L <name>`, and
  `sqlite3 $H/ledger.db "insert or replace into meta(key,value) values('setup.seen','99');"`.
- Write like the surrounding code: plain-English doc comments in short sentences, short names,
  commit subjects in the repo's style (`git log --oneline -15`). No attribution lines.
- Gates, at the end of every task: `cargo fmt --all --check`;
  `cargo clippy --workspace --all-targets -- -D warnings`; `cargo test --workspace` (from
  `code/`, after `cargo build --workspace` so daemon tests find `rl-session` — a test that prints
  "skipping: rl-session not built" did not run). At the end of the PR also, on Linux:
  `find code -name '*.rs' -exec touch {} +; ./scripts/ci all`.
- Never bare `git stash`. Branch names must not contain "git".

## Review Focus

- **A flow edited mid-firing.** The firing finishes on the definition it started with
  (`firings.def_json` snapshot), never half old, half new. Test: Task 8
  `an_edit_mid_firing_leaves_that_firing_as_it_started`.
- **A restart while a step's run ends.** `rld` down, the step's run ends, `rld` up: the next step
  starts exactly once — reconcile and the event loop both see the end. Test: Task 10
  `a_restart_mid_firing_carries_on_once`.
- **An ask dismissed, or expired with no default.** The step is `skipped`, what comes after it
  is skipped, and the firing ends `done` — it never hangs `waiting`. Test: Task 9
  `a_dismissed_ask_ends_the_firing`.
- **Spliced output that looks like a placeholder.** A probe whose output contains
  `{triage.out}` is put into the prompt literally, not expanded again. Test: Task 4
  `spliced_text_is_not_expanded_again`.
- **A changed script.** Editing `new-log-errors.sh` (not `flow.md`) by hand makes the flow
  `needs approval` and `when` stops firing it until approved. Test: Task 7
  `a_changed_script_asks_again`.

```rust
/// `flow.md` as written: the frontmatter, and the prompt under each `## ` heading.
#[derive(Debug, Clone, PartialEq)]
pub struct Doc {
    pub spec: FlowSpec,
    /// `triage`, `review.apply` → the text under the heading, trimmed.
    pub sections: BTreeMap<String, String>,
    /// The line (1-based, in flow.md) each step's key is on, for errors.
    pub lines: BTreeMap<String, usize>,
}

/// What did not read, and where.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Problem {
    pub line: Option<usize>,
    pub column: Option<usize>,
    pub message: String,
}

pub fn read(text: &str) -> Result<Doc, Problem>;
```

Rules: the file must start with a line `---`; the frontmatter ends at the next line `---`; a
missing end is `Problem { line: Some(1), message: "the frontmatter has no closing ---" }`. The
frontmatter is parsed with `serde_norway::from_str::<FlowSpec>`; a YAML error's location is
offset by the opening line, and its message has the location taken out (copy
`rulestore.rs:246`'s trimming). A section is a line starting `## ` followed by a name
`[a-z0-9][a-z0-9.-]*`; its text runs to the next `## ` line or the end; text before the first
heading is a description and ignored. `lines` is found by scanning the frontmatter for a line
that is exactly two-space-indented `<name>:` under `steps:`.

```rust
// template.rs
/// A `{head.rest}` reference: `{probe.out}` is ("probe", "out"), `{event.data.x}` is ("event", "data.x").
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct Ref { pub head: String, pub rest: String }

/// What a placeholder stands for, looked up when it is spliced.
pub trait Lookup { fn get(&self, r: &Ref) -> Option<String>; }

/// The references in `text`: `{` + head + `.` + rest + `}`, head `[a-z0-9-]+`, rest `[a-z0-9_.-]+`.
/// Anything else in braces (`{print $1}`, `{}`) is not one.
pub fn refs(text: &str) -> Vec<Ref>;

/// `text` with each reference replaced by what `lookup` says, in one pass — what is spliced in
/// is never read for references again. One `lookup` knows nothing of is left as written.
pub fn fill(text: &str, lookup: &dyn Lookup) -> String;

// cond.rs
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub enum Cond { Set(Ref), Unset(Ref), Is(Ref, String), IsNot(Ref, String) }

/// `probe.out`, `!probe.out`, `review.choice == apply`, `probe.severity != low` (a value may be
/// quoted). Anything else is refused, saying what is allowed.
pub fn parse(s: &str) -> Result<Cond, String>;

impl Cond {
    pub fn subject(&self) -> &Ref;
    /// Set: there is a value and it is not empty once trimmed.
    pub fn holds(&self, lookup: &dyn template::Lookup) -> bool;
}
```

```rust
/// What happened to a firing.
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Happened {
    Started,
    /// A step's run ended; `ok` when it finished well.
    Ended { step: String, ok: bool },
    /// A step's run was stopped by hand: the firing stops.
    Stopped { step: String },
    /// An ask step was answered with an option that runs something.
    Answered { step: String },
    /// An ask step was answered with an option that does nothing.
    AnsweredNothing { step: String },
    /// An ask step was dismissed, or expired with no default.
    Unanswered { step: String },
    Lost { step: String },
    Resumed { step: String },
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Do {
    /// Start this step's run (a `Run` step).
    Start(String),
    /// Raise this step's question.
    Ask(String),
    /// Start the chosen option's run, as this step's own.
    RunOption(String),
    /// The firing is over.
    End(FiringStatus),
}

/// Moves `steps` on from what happened and says what to do. `facts` answers the `if:`s.
/// Pure: calling it twice with the same `Happened` on the result of the first does nothing new.
pub fn advance(def: &FlowDef, steps: &mut BTreeMap<String, StepStatus>, h: &Happened,
               facts: &dyn Lookup) -> Vec<Do>;

/// The firing's status from its steps (for the ledger row and the list).
pub fn status(steps: &BTreeMap<String, StepStatus>) -> FiringStatus;
```

Rules (from the spec's "The engine"):
- `Started`: every step starts `Pending`; then readiness.
- Readiness, repeated until nothing changes: a `Pending` step whose `after` are all `Done` —
  its `if:` false → `Skipped`, and every `Pending` step downstream of it → `Skipped`; true → `Run`
  step `Running` + `Do::Start`, `Ask` step `Waiting` + `Do::Ask`. A `Pending` step with any
  `after` `Skipped` or `Failed` → `Skipped`.
- `Ended{ok:true}` → `Done`; `ok:false` → `Failed`. `Answered` → `Running` + `Do::RunOption`.
  `AnsweredNothing` → `Done`. `Unanswered` → `Skipped`. `Lost` → `Lost`. `Resumed` → `Running`.
  `Stopped` → that step `Failed`, every `Pending` → `Skipped`, and `End(Stopped)` once nothing
  runs.
- A `Happened` about a step not in the state it expects (e.g. `Ended` for a `Done` step) changes
  nothing and returns nothing — this is what makes a replayed event harmless.
- `End(..)` is returned once, when the last step leaves `Pending/Running/Waiting/Lost`:
  `Failed` if any step `Failed`, else `Done` (or `Stopped` after a stop).
- `status`: any `Waiting`/`Lost` and none `Running`/`Pending` → `Waiting`; any
  `Running`/`Pending` → `Running`; else as `End`.
