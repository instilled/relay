# Catch-up Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Opening the panel after being away shows what happened since, as a few bullets, then a
line per project and per job/agent/shell/question; `/summary [deep] [stretch]` on any row says
more, since you last interacted with it.

**Architecture:** Three PRs, each from `origin/main` after the previous merges. (A) renames the
summariser job `summarise` → `summary` everywhere. (B) generalises `summary.make` to targets (run,
job, project, all), two levels (brief, deep) and a default stretch per target, kept in a new
`summary_kept` table; `/summary` and `rl summary` use it. (C) adds `catch_up` config, a pure
client-side catch-up tree built from `digest.get`, a `View::CatchUp` the panel opens on when you
were away longer than `catch_up.after`, the auto top summary, `/since`, and `rl since` printing the
same tree.

**Tech Stack:** Rust workspace (`code/`): `rl-proto` (types, RPC methods, config), `rl-ledger`
(SQLite via rusqlite, numbered migrations), `rl-daemon` (`rld`, tokio, handlers), `rl-cli` (`rl`,
ratatui panel under `src/tui/`). Tests: `cargo test --workspace`; daemon integration tests use
`code/rl-daemon/tests/common` (`Harness`, `Conn`); fake agents use `code/fixtures/fake-agent`.

**Spec:** `docs/specs/2026-10-06-catch-up.md` — read it before starting; this plan argues from it.

## Global Constraints

- Never invoke a real agent in a test. The summariser in tests is `code/fixtures/fake-agent`
  registered as a detect profile (see `code/rl-daemon/tests/summarise.rs:17-56`).
- Never touch `~/.relay`; live checks use `RELAY_HOME=/tmp/<x>` and `tmux -L <name>`; skip setup
  with `sqlite3 $H/ledger.db "insert or replace into meta(key,value) values('setup.seen','99');"`.
- No alias and no migration code for the rename: `/summarise`, `rl summarise`,
  `assistants.summarise` and `assistant:summarise` simply stop existing. (The one existing install
  is moved by hand after PR A merges — not part of any task.)
- Config defaults: `catch_up.after: 8h`, `catch_up.summary: auto`; `after: off` (or `never`)
  disables the automatic open; `summary` is `auto | ask`; unknown keys refused
  (`deny_unknown_fields`).
- Write code like the surrounding code: plain-English doc comments, short names, the repo's
  commit-subject style (`git log --oneline -15`). No attribution lines in commits or PRs.
- Gates per PR: `cargo fmt --all --check`; `cargo clippy --workspace --all-targets -- -D warnings`;
  `cargo test --workspace`; Linux: `find code -name '*.rs' -exec touch {} +` then
  `./scripts/ci all` (one agent at a time — the Docker target volume is shared).
- `PROTOCOL_VERSION` (`code/rl-proto/src/lib.rs:21`) goes 2 → 3 in PR B (`SummaryParams` changes
  shape).
- Never bare `git stash`. Branch names must not contain "git".

## Review Focus

- **Away boundary is read before it is overwritten.** `run()` touches presence on open
  (`tui/mod.rs:926`), which returns the *previous* `last_seen_at` and stores now. The catch-up
  must use the returned previous value; using `presence.get` afterwards would always say "0s
  away". Test: Task C3 `away_is_the_presence_before_this_open`.
- **First ever open (no presence row).** `last_seen_at` is `None`: no catch-up (there is nothing
  to catch up on), not "away since 1970". Test in Task C3.
- **A deep summary over a long stretch** must not send one giant prompt: material over
  `CHUNK` is split, each part summarised, then joined. Test: Task B2
  `deep_over_a_long_output_is_read_in_parts`.
- **Deep over many rows asks first.** `/summary deep` on a project or the top with more than one
  run says how many assistant calls it will make and waits for `y`. Test: Task B4
  `deep_over_many_rows_asks_first`.
- **A stretch with nothing in it** says so without asking an assistant, at every target. Test:
  Task B2 `nothing_in_the_stretch_asks_no_one` (run, job, project, all).

Rules (from the spec):
- **Run, brief**: today's path (`claude_recap` free; else assistant) over `from` (default `run.seen_at`, else whole run). Kept in `summaries` as today when `from` is None, else in `summary_kept`.
- **Run, deep**: material = Claude `claude_messages` *with tool use* (add `transcript::claude_story(text, from) -> String`: user/assistant messages plus one line per `tool_use` — name and first 120 chars of its input — and per `tool_result` error), Codex `codex_facts` plus each turn's message, else `session_io::tail_since(from, usize::MAX)`; plus up to 500 events. If material > `CHUNK`, split on line boundaries into `CHUNK` parts, summarise each with `prompt(... heading = "Part i of n")`, then summarise the parts' answers with `prompt_over`. Always an assistant.
- **Job** (`cause = schedule:<name>` / `reaction:<name>`, `workspace` matches `run.workspace` or the rule is global): runs from `runs::list_for_digest(c, from)` filtered by cause/workspace; default `from = oldest_unseen(...)` else `now - 24h`.
- **Project**: runs from `list_for_digest(c, from)` with `run.workspace == workspace`, assistants' own runs excluded. `from` required (error `"a project's summary needs where to start (from)"`).
- **All**: every run from `list_for_digest(c, from)`, assistants' own excluded, grouped by workspace. `from` required.
- **Over many (job, project, all)**: brief reads each run's brief line (`summaries::lines` recap, else the digest's one-line status via `crate::digest::summarise(run, last, emitted)`) — no per-run assistant call — and makes one `prompt_over` call. Deep first makes each run's deep summary (kept ones reused), then one `prompt_over` call. `calls` = calls actually made (or, `dry`, would be made: deep = runs without a kept deep summary + 1; brief = 1).
- **Nothing in the stretch**: no runs (or empty material) → `agent: "relay"`, `source: "nothing new"`, text `"nothing happened since <clock>"` — no assistant.
- **Kept**: given back when `!again` and `reach` unchanged; `reach` for many = `"n:<run count>:<max state_at ms>"`.

`prompt_over(what: &str, from: Option<Timestamp>, lines: &[(String, String)]) -> String` asks: "You are telling the person what happened in {what} since {clock}, who has not looked. Answer with 3–6 bullets, most important first: what needs them, then what broke, then what moved or shipped. One line each, no preamble." followed by `## <title>\n<line>` per entry.
