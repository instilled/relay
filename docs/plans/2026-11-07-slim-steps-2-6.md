# Slim relay · steps 2–6 — daemonless `rl`, the list, native sessions, the switch, messaging — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Relay becomes `claude agents` for every harness plus shells plus messaging, with no daemon:
the `rl` binary, `rl-session` holders and plain files under `~/.relay`. Everything else is deleted.

**Spec:** `docs/specs/2026-11-07-slim-relay.md` (on `chore/roadmap`; a copy of the relevant facts is
inlined per task). **Ships in the same PR as step 1 (#199, branch `slim-step-1`).**

**Architecture:** A new crate `code/rl` is built beside the old ones (Tasks 5–15). Its binary is
named `rl-new` until the switch (Task 16) deletes `rl-cli`/`rl-daemon`/`rl-proto`/`rl-ledger`/
`rl-flow` and renames it `rl`. Code is **moved** from the old crates (copy the file, cut what the
spec drops), never refactored in place. `rl` talks to holders directly over their socket
(`rl_session::client`), reads hook state files, and asks Claude/Codex for their own sessions.

**Tech stack:** Rust 2024, tokio, clap, serde/serde_json, ratatui 0.30, crossterm 0.29 (patched
`vendor/crossterm`, keep the patch), jiff, `notify` (file watch; new dep), regex.

- Harness note: the shell may refuse compound commands and heredocs into files; one simple command per call; write files with the file tool.

## Facts from the code survey (2026-11-07)

**Holder (`rl-session`)** — library crate; `client::Session::{attach(&Path, replay: bool), attach_screen(&Path, from: u64)} -> Result<(Hello, Session)>`, `recv/send/input/resize/signal/close`, `split()`. Dropping the connection = detach. Frames: client sends `Attach` first (anything else → silent close); holder replies `Hello{id,pid,holder_pid,cols,rows,tty,started_at,exit?,total,replay_from}`, replay, `ReplayEnd`, `Exit?`, `Foreground?`, live. `Close` frame: SIGHUP the child group, wait ≤5s, remove socket, exit. Spawning: run the `rl-session` binary (`rl_core::locate_bin("rl-session","RELAY_SESSION_BIN")`) with stdin/stdout null and stderr to a log; it exits 0 once ready (socket bound, child spawned), non-zero with `err: <msg>` otherwise. Flags: `--id --socket --exit-file --cwd --cols --rows --env K=V… --linger <s> --detect <file> --state-file <path> -- argv`. Removing the socket file makes the holder shut down (checked every 60 s). A client >4096 chunks behind is dropped. `exit` JSON: `{code, signal?, at}`; `state.json`: `StateFile{state, confidence, detail?, last_line?, foreground?, at}`. `DetectSpec::from_parts(kind, &Patterns, Timing)` builds the `--detect` JSON from `rl_detect::Registry::resolve(kind, argv).profile.{patterns,timing}`.

**Attach (`rl-cli/src/attach.rs`)** — reusable verbatim: `Newlines`, `AltScreen::{watch,leave}`, `DETACH = 0x1c`, `Ended`/`.code()`, `client_name()`, `title()` (`\x1b]0;…\x07`), `dim()`, `AbortOnDrop`, `RawMode`, `leave()`, `Status` (minus `need`), and the `select!` loop (frames; stdin split at DETACH; SIGWINCH → Resize; initial Resize). It never sent `Attach` itself (rld did) — the direct client must (`attach_screen(sock,0)` for tty sessions, `attach(sock,true)` otherwise). Port the young-run resize nudge from `rl-daemon/src/attach.rs:34-43,315-325` (session <3 s old: resize rows-1 then back after 200 ms). `rl-cli/src/held.rs` (native attach on a local PTY; `hold(argv, name) -> Back{Detached, Ended(Exit)}`) moves as is.

**Hooks** — `rl-cli/src/hook.rs`: pre-clap `args()`, `words()`, must never fail/print, 1500 ms budget, ignores calls when `RELAY_ASKING` is fresh, pid lookup via `ps -A -o pid=,ppid=,args=` + `agent_among` on start/prompt events, stdin fields `session_id`, `cwd` (Gemini: env `GEMINI_SESSION_ID`/`GEMINI_CWD`), `transcript_path`, `detail` = `UserHooks::detail(event,payload)`. Event → state via `rl_detect::sessions::UserHooks::told` (`started`/`idle` → idle, `working`/`carries-on` → busy, `needs` → waiting, `ended` → gone). Installer: `rl_detect::user_hooks::{install, uninstall, installed}`; command line `'<rl>' hook <agent> <Event>[ --user] || true`. `rl_detect::claude::settings_json/write_settings` = per-session `--settings` hooks for Relay-started Claude. Outside-session liveness: `kill(pid,0)`, EPERM = alive (`rl-daemon/src/outside/hooked.rs:376`); prune rules there (`STALE` 12 h without pid, `QUIET` 48 h with pid).

**Claude native** — `claude agents --json --all` → `[{id(8 hex), sessionId, name, cwd, kind:"background", startedAt(ms), state: working|blocked|done, pid?, status?: idle|busy}]` (parse: `rl-daemon/src/outside/claude.rs:24-98`). `~/.claude/jobs/<id>/state.json` (honour `CLAUDE_CONFIG_DIR`): `detail` (one-line summary), `state`, `tempo`, `needs?`, `children: [{id, href, kind: "pr"|…, title?}]|null`, `createdAt`, `updatedAt`, `lastTerminalAt?`. No PR open/merged state anywhere. `claude attach <id>`; `claude --bg [-n <name>] [prompt]` starts a background session; `claude --resume <session-id> --bg` carries one on. Polling: run with env `RELAY_ASKING=<unix secs>` so its own hooks are ignored.

**Codex native** — codex-cli 0.167. `codex agents` is TUI-only (no `--json`). App-server control socket `~/.codex/app-server-control/app-server-control.sock`; `codex app-server proxy` bridges stdio to it (JSON-RPC); `codex app-server generate-json-schema --out <dir>` gives the API. `codex resume <id|name>` opens one thread (through the shared daemon by default).
