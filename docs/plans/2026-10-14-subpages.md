# Full-width subpages, no side column, Watch dropped: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** a selected row's detail is a full-width **subpage** you enter and leave — the same enter/leave model as `attach`/`join` — instead of a pane shown beside the list. The glanceable side column goes; the list owns the full width until you enter a row. `AttachMode::Watch` is removed end to end (the `rl watch` verb, the daemon arm, and the in-panel live-watch `TermView`), and an **ended** run's output becomes a static render of its journal instead of a live Watch stream.

**Architecture:** the panel already draws a full-width pane when `wide` is set (`areas()` collapses the split), and the daemon already serves an ended run as a one-shot pre-rendered screen plus an `Exit` frame (it never reads the attach mode). So the change is: (1) make "pane shown" always mean full-width with the list hidden, remove the side-by-side split, and route keys to the subpage while it is up; (2) turn `TermView` from a long-lived Watch stream into a one-shot static reader fed from the daemon's ended-run response; (3) delete `AttachMode` and the `mode` field now that live attach is always a join. Live-run enter is unchanged — it still hands the real terminal over (`self.attach`), which is itself the original subpage.

**Tech Stack:** Rust, ratatui, vt100. Crates: `rl-cli` (panel + CLI), `rl-proto` (wire), `rl-daemon` (rld), `rl-ledger` (`session_io`), `rl-session` (`screen`).

**Spec:** none written; this plan is the agreed design from the 2026-10-14 discussion, recorded in the `pane-redesign-direction` memory. Rulings below stand in for a spec.

**Depends on:** PR #168 (`held.rs`, the `attach_outside` handover, the `pub(crate)` attach helpers). ## Rulings (settle these once, here)
- **R1 — AttachMode is deleted, not reduced.** Live attach becomes unconditionally a join; the `mode` field is removed from `AttachParams`. The reviewer flagged this as a wire change (the field has no serde default). It is acceptable: `rld` is spawned and version-matched by `rl` (`daemon::ensure`), and the two ship as one binary. Task 5 bumps the protocol version constant if one exists and otherwise forces an `rld` restart in `ensure`. Cost if wrong: a stale `rld` rejects `run.attach` until restarted — recoverable by `rl` restarting it.
- **R2 — `rl watch` is removed, not kept as a CLI verb.** Per the user: "drop it, we can rebuild if necessary." Non-interactive piping (`rl watch id | tee`) and read-only viewing go with it. `rl join` remains the only way into a run from the CLI.
- **R3 — An ended run's output is a static render, not a live view.** It is read once from the journal (`session_io` → `Screen::render`), drawn, and scrolled; the daemon connection is closed immediately. No `pump`/`over`/`lost`/live-resize.
- **R4 — "Pane shown" always means full-width; the list is never drawn beside it.** `wide`, `share`, `SPLIT_AT`, `LIST_SHARE`, `LIST_SHARE_TERM` and the horizontal split arm all go. A subpage carries a one-row header (`‹ esc  <title>`) so you know where you are and how to leave.
- **R5 — selection is kept across enter/leave.** Entering a row's subpage and pressing `esc` returns to the list with the same row selected, as leaving a join does today.

## Review Focus
- **A terminal too short for a subpage's header + body** — the header row must never squeeze the body to zero; a 1-row terminal still draws something sane. (Task 2.)
- **An ended run with no journal rows** (pruned, or never wrote output) — the static reader shows "nothing was recorded", not an error or an empty hang. (Task 1.)
- **`esc` with a sub-mode active** (`Mode::Answer`, `Mode::Walk`, a half-typed rename inside a subpage) — `esc` leaves the sub-mode first, then the subpage, never the panel. (Task 3.)
- **A live run that ends while you are joined** — returning lands on the list, not on a dead join; re-entering shows the static output. (Tasks 1, 3.)
- **A key pressed while a subpage owns the screen** — list-only chords (`j`/`k` navigation, `/` command line) do not leak to the list underneath; the subpage's own keys (scroll, answer, walk) win. (Task 2.)

### Task 1: an ended run's output is a static subpage, not a live Watch stream

The live-watch machinery is removed.
