# Catch-up: what happened while you were away

Status: design, for review · 2026-10-06

## Why

Relay's worth is work that goes on without you — schedules, reactions, agents left running — and
the moment that pays off is coming back: the next morning, after a weekend, after a holiday. Today
the panel says `3 new` and `rl since` prints a digest; there is no one place that says, in a
glance, what moved, what broke, what waits on you, with more on demand. This is that place.

It comes before workflows (flow files with a review step) on purpose: catch-up is where reviews get
answered, so it fixes what every unattended run must leave behind — one outcome line, and a
question when it needs you — before the flow file is designed.

## What you see

Opening the panel after being away longer than `catch_up.after` (default 8h) shows the catch-up
instead of the list. `/since [stretch]` shows it any time; `esc` goes to the list.

```
  while you were away · since Fri 18:40 (2d 15h)                              esc to the list
  ──────────────────────────────────────────────────────────────────────────────────────────
  • 2 need you: deps update ready to ship (api) · prod-logs asks whether to page
  • flint-platform: 3 agent branches ready; nightly tests failed twice, green since Sat
  • relay: nothing ran
  • gchat mentions: 14 checks, 2 answered for you
                                                                    by haiku · from 23 lines
  ──────────────────────────────────────────────────────────────────────────────────────────
  ▾ flint-platform                                        2 need you · 9 ran · 1 failed
      ? prod-logs        asks: page on-call for the 502 spike?          1-3 answers   2h
      ✦ claude: deps     ready: bumped 14 deps, tests green, branch deps/oct   review  5h
      ↻ nightly tests    ✓✓××✓✓✓  failed Fri, Sat · green since                      1h
      ❯ ~/flint-platform  ran 6 commands · last: cargo test                          2d
  ▸ relay                                                 nothing new
  ▸ everywhere                                            14 ran · quiet
```

Three levels, each costing more and asked for only when wanted:

1. **The summary** — 3–6 bullets, just enough context: what needs you first, then what moved,
   broke or shipped, by project. Written by `assistants.summarise` from the level-2 lines (a few
   hundred tokens in), when `catch_up.summary: auto` and you were away longer than
   `catch_up.after`; otherwise Relay writes the bullets from counts alone and `/summary` on the
   top asks the assistant.
2. **A line per project, and under it a line per job, agent, shell and question** — never an
   assistant call:
   - an agent: its own recap's first line (#142), else its state and last line;
   - a job: its firings as marks (`✓✓××✓`) and how the last went;
   - a shell or command: what ran (count, the last command) and how it ended;
   - a question: what it asks, answerable here by number, with a note, as on the list.
   Projects with nothing new fold to one line; what needs you is first in each, and projects
   that need you come first.
3. **`/summary [depth] [stretch]` on any row** — see below.

Enter on a row goes to it on the list (or the graph, for a rule); everything the catch-up showed
counts as seen once you leave it.

## `/summary`: any row, three depths

`/summary` replaces `/summarise` (which stays as an alias), and works on the catch-up's top, a
project, a job, an agent, a shell or a command — on the list and in the catch-up alike. The
stretch defaults to *since you were last here*; `/summary 2 3d` names one.

| depth | reads | says |
|---|---|---|
| `1` (default) | the rows' recaps, firings and outcomes | 2–3 lines, just enough context |
| `2` | what was said: an agent's turns, the commands, the events | what happened, step by step |
| `3` | everything: tool calls, files touched, diff stats, the output's tail | the full story, what changed where |

- A run at depth 1 is its agent's own recap where it has one (free); otherwise, and at 2 and 3,
  it is `assistants.summarise` reading that much.
- A project or a job is summarised from its rows' summaries at the same depth (made first where
  missing), so a wide summary stays a small prompt until you go deep.
- The top is the projects' depth-1 lines, or deeper on request.
- Shown in the pane, marked `depth 2 · by haiku · 3m ago` (or `claude's own`); the top's in the
  catch-up's header.
- Kept: an answer is kept by (what, depth, stretch) and given back while what it covers has not
  moved on; `/summary again` makes a new one.

## Configuration

```yaml
catch_up:
  after: 8h         # away longer than this: the panel opens on the catch-up
  summary: auto     # auto: the assistant writes the top when it opens · ask: only on /summary
```

Absent means these defaults. `after: off` never opens it by itself (`/since` still does).
Setup gains no step; `rl config` shows the resolved values.

## How it is built

- **Away.** `presence` already keeps when each client last left the panel; `rl since` counts
  from it. The panel reads it on open (`presence.touch` returns the last one) and decides.
- **Catch-up data.** A new `catchup.get {since}` returns the level-2 tree in one call: projects,
  under each its rows since then with their outcome line, marks and needs-you flag, and the kept
  top summary if one covers this stretch. Built from the same queries as `digest.get` plus the
  `summaries` recap lines (#142), so no per-row queries and no transcript reading.
- **Summaries.** `summary.make` grows a target (`run`, `job`, `workspace`, `all`) and a `depth`;
  `summaries` grows a key for the target, depth and stretch (migration), keeping today's run rows
  as depth-1 run summaries. Making the top is an assistant run like any (`cause:
  assistant:summarise`), started by `rld` when the panel asks for a catch-up and the config says
  auto; the panel shows the catch-up at once and fills the top when it lands.
- **CLI.** `rl since [stretch]` prints the same tree (and the top, waiting for it up to the usual
  timeout when auto); `rl summary <run|job|folder|all> [--depth N] [stretch] [--again]`, with
  `rl summarise` kept as an alias.

## Not in this

- Pushing the catch-up to you (Slack, mail, phone) — a reaction can already; a built-in
  `notify:` comes with workflows.
- Workflows and the review step — next, designed against what this shows.
- Remembering per-row "seen" beyond today's unseen marks.

## Testing

- Pure: the catch-up tree from a seeded ledger (order, folding, needs-you first, marks, lines);
  the top's bullets written from counts with no assistant.
- Daemon: `catchup.get` over a stretch; `summary.make` per target and depth with a fake
  summariser (never a real agent); kept answers given back until the row moves on; auto top
  started only past `catch_up.after`.
- Panel: opens on the catch-up when away longer than `after`, not otherwise; `esc`, enter,
  answering a question in it; `/summary` depths on each row kind; `/summarise` alias.
- Live, in an isolated `RELAY_HOME` with `presence` set back two days.
