# Catch-up: what happened while you were away

Status: design, for review · 2026-10-06

## Why

Relay's worth is work that goes on without you — schedules, reactions, agents left running — and
the moment that pays off is coming back: the next morning, after a weekend, after a holiday. Today
the panel says `3 new` and `rl since` prints a digest; there is no one place that says, in a
glance, what moved, what broke, what waits on you, with more on demand. This is that place.

It comes before workflows (flow files with a review step) on purpose: catch-up is where reviews get
answered, so it fixes what every unattended run must leave behind — one outcome line, and a
question when it needs you — before the flow file is designed.

## What you see

Opening the panel after being away longer than `catch_up.after` (default 8h) shows the catch-up
instead of the list. `/since [stretch]` shows it any time; `esc` goes to the list.

```
  while you were away · since Fri 18:40 (2d 15h)                              esc to the list
  ──────────────────────────────────────────────────────────────────────────────────────────
  • 2 need you: deps update ready to ship (api) · prod-logs asks whether to page
  • flint-platform: 3 agent branches ready; nightly tests failed twice, green since Sat
  • relay: nothing ran
  • gchat mentions: 14 checks, 2 answered for you
                                                                    by haiku · from 23 lines
  ──────────────────────────────────────────────────────────────────────────────────────────
  ▾ flint-platform                                        2 need you · 9 ran · 1 failed
      ? prod-logs        asks: page on-call for the 502 spike?          1-3 answers   2h
      ✦ claude: deps     ready: bumped 14 deps, tests green, branch deps/oct   review  5h
      ↻ nightly tests    ··××···  failed Fri, Sat · green since                      1h
      ❯ ~/flint-platform  ran 6 commands · last: cargo test                          2d
  ▸ relay                                                 nothing new
  ▸ everywhere                                            14 ran · quiet
```

Three levels, each costing more and asked for only when wanted:

1. **The summary** — 3–6 bullets, just enough context: what needs you first, then what moved,
   broke or shipped, by project. Written by `assistants.summary` from the level-2 lines (a few
   hundred tokens in), when `catch_up.summary: auto` and you were away longer than
   `catch_up.after`; otherwise Relay writes the bullets from counts alone and `/summary` on the
   top asks the assistant.
2. **A line per project, and under it a line per job, agent, shell and question** — never an
   assistant call:
   - an agent: its own recap's first line (#142), else its state and last line;
   - a job: its firings as the list's marks (`··××·`) and how the last went;
   - a shell or command: what ran (count, the last command) and how it ended;
   - a question: what it asks, answerable here by number, with a note, as on the list.
   Projects with nothing new fold to one line; what needs you is first in each, and projects
   that need you come first.
3. **`/summary [deep] [stretch]` on any row** — see below.

Enter on a row goes to it on the list (or the graph, for a rule); everything the catch-up showed
counts as seen once you leave it.

## `/summary`: any row, brief or deep

`/summary` replaces `/summarise`, which goes (no alias), and works on the catch-up's top, a
project, a job, an agent, a shell, a command or a question — on the list and in the catch-up
alike. `/summary` is brief; `/summary deep` reads the logs. Either takes a stretch
(`/summary deep 3d`).

**The stretch, by default, is since you last interacted with what is summarised.** For a run
that is when you last looked at it (`runs.seen_at`: selected, joined or watched); for a job, its
runs' — the oldest unseen firing on; for a project and the top, when you last left the panel
(`presence`). So a run you checked last night is not retold from Friday.

| | reads | says |
|---|---|---|
| **brief** | the rows' recaps, firings and outcomes | 2–3 lines, just enough context |
| **deep** | the logs of the stretch: an agent's session file (its turns, tool calls, files touched), a shell's or command's recorded output (the commands, their output, exit codes), a question's asking and answer, and Relay's events for each | what happened, in order, and what changed where |

- A run, brief, is its agent's own recap where it has one in the stretch (free); otherwise, and
  always when deep, `assistants.summary` reads it.
- Deep reads everything in the stretch. Past what one prompt holds, it is read in parts, each
  summarised, then those summarised — so a weekend of a busy agent is still one answer.
- A project or a job is summarised from its rows' summaries at the same level (made first
  where missing), so brief stays a small prompt. Deep over many rows is one assistant call per
  row and one to join them, so the panel says so first (`deep over 12 runs · 13 calls · y?`).
- The top is the projects' brief lines, or deep on request (asked first, as above).
- Past deep there is no more summary, only the source: enter joins the run's terminal, and the
  pane shows its facts.
- Shown in the pane, marked `deep · by haiku · since 22:14 · 3m ago` (or `claude's own`); the
  top's in the catch-up's header.
- Kept: an answer is kept by (what, brief or deep, stretch) and given back while what it covers
  has not moved on; `/summary again` makes a new one.

## Configuration

```yaml
catch_up:
  after: 8h         # away longer than this: the panel opens on the catch-up
  summary: auto     # auto: the assistant writes the top when it opens · ask: only on /summary
```

Absent means these defaults. `after: off` never opens it by itself (`/since` still does).
Setup gains no step; `rl config` shows the resolved values.

## How it is built

- **Away.** `presence` already keeps when each client last left the panel; `rl since` counts
  from it. The panel reads it on open (`presence.touch` returns the last one) and decides.
- **Catch-up data.** No new call: the panel (and `rl since`) asks `digest.get {since}` for the
  stretch and builds the tree on the client (`rl-cli/src/catchup.rs`, pure), with the list's own
  grouping and job folding (`rows::build`), so the catch-up and the list never disagree. The
  outcome lines are the digest's (`summary`, `recap`), so no transcript is read for it.
- **Summaries.** `summary.make` grows a target (`run`, `job`, `workspace`, `all`) and `deep`;
  the stretch defaults per target as above. `summaries` grows a key for the target, the level and
  the stretch (migration), keeping today's run rows as brief run summaries. Making the top is an assistant run like any (`cause:
  assistant:summary`), started by `rld` when the panel asks for a catch-up and the config says
  auto; the panel shows the catch-up at once and fills the top when it lands.
- **CLI.** `rl since [stretch]` prints the same tree (and the top, waiting for it up to the usual
  timeout when auto); `rl summary <run|job|folder|all> [--deep] [stretch] [--again]` replaces
  `rl summarise`, which goes.
- **The name, everywhere.** The assistant's job is `summary` too: `assistants.summary` in
  `config.yaml`, cause `assistant:summary`, `summarise` gone from the words, the context pack and
  setup. There is no release yet, so no alias and no migration code: the one existing install is
  moved by hand when this merges (the key in `~/.relay/config.yaml`, and the cause of past
  assistant runs in the ledger).

## Not in this

- Pushing the catch-up to you (Slack, mail, phone) — a reaction can already; a built-in
  `notify:` comes with workflows.
- Workflows and the review step — next, designed against what this shows.

## Testing

- Pure: the catch-up tree from a seeded ledger (order, folding, needs-you first, marks, lines);
  the top's bullets written from counts with no assistant.
- Daemon: `catchup.get` over a stretch; `summary.make` per target, brief and deep, with a fake
  summariser (never a real agent); kept answers given back until the row moves on; auto top
  started only past `catch_up.after`.
- Panel: opens on the catch-up when away longer than `after`, not otherwise; `esc`, enter,
  answering a question in it; `/summary` and `/summary deep` on each row kind; the default stretch per row (seen, presence); `/summarise` is no longer a command.
- Live, in an isolated `RELAY_HOME` with `presence` set back two days.
